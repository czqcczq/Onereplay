一、安全性实验结果：

使用的benchmark：
1. AdvBench，数据格式为直接让模型执行一个有害行为。
2、HarmBench，分三类，Standard，Contextual 和 Copyright，其中 Standard 和 其他两个数据集更相似，直接给一个危险请求；Contextual 则是给 context string + referencing behavior string，类似于给一段内容，然后让模型安装有害 behavior 要求去修改这段内容；Copyright 是为了判断模型能不能保护版权行为。
3、SORRY-Bench，和Adv相似，但是其官方设计了每个安全类别恰好 10 条，因此不会因为某一个危险类别样本特别多而主导整体结果

我的判分是学习 NSPO 这篇工作的方式，Adv 和 HB 用 GPT4 judge方式（NSPO的prompt），模型生成结果调用API让GPT判断。SORRY-Bench 则是用官方提供的微调后的 Mistral-7B evaluator 作为判别器。指标是统一的，都是 ASR，0 = 没有成功满足危险请求，1 = 成功产生危险回答，ASR = 产生危险回答的题目 / 总题目，所以都是越低越好。

2.1、关于 EWC 和 replay 的额外实验
EWC：我分了 half 和 equal 两种类型，half 是直接0.5if + 0.5math，equal 则是根据 Fif 和 Fcode 的特点，取 mean（Fif）/ mean（Fcode）（= 3+） 的反比，因为我的本意是希望 Fmix 能做到 if 领域和 math 领域等重要的，Fif 的大小在大部分层数（55/56）上都比 Fcode 大，所以如果直接等权混合肯定是让 Fmix 更偏向 if 领域的，但是我不知道这样的做法有没有道理就 half 和 equal 都做了。
replay 也是同样道理，math 的 mean len 要长于 if，因为算 loss 的时候会取长度的平均，所以理论上 math 天然占比要大，为了确保二者同程度，我做了0.8if + 0.2 math的 replay 混合。

EWC equal：gsm8k：0.7839272175890827 ；math-500：0.678
EWC 的 equal 效果没有 half 好，我个人的分析为，当前实验的配置下，很难判断出模型的数学能力，相当于更强的 if 保护 + 一定的 math 保护能让 EWC 反而在 gsm 和 math 上表现更好，所以很可能 lora 训练没有影响模型的数学能力，只是让模型不知道怎么去给出标准的答案格式或者答题格式，这更多还是回到 if 的能力上，所以我下面准备做 agentic 的保护工作，看能不能替换了 math 领域。
    为了验证推断，我跑了 ewc 两个在 ifeval 上的得分，结果如下：

可以看到 half 在 if 上的表现确实更好，if 能力更强，所以我也做了 onereplay 的 0.75if + 0。25math 混合，训练后评测结果：
