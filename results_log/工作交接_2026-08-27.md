# 第一部分　已确立的主结论（数学线）

## 一句话

在 Qwen3-1.7B + LoRA(r=8, q/v) + Commonsense170k 这个设置下，微调遗忘的**不是数学能力，而是生成行为**——愿不愿意写长回答、能不能按要求收尾。准确率基准因为判分器的宽松兜底几乎完全看不见这件事；对 base 自身输出的交叉熵探针能看见，量化为 **7.5 倍**漂移，OneReplay 消除其中 **62~72%**。

## 1.1 数学能力没被遗忘（三个独立量具一致）

| 量具 | base | vanilla | 显著性 |
|---|---:|---:|---|
| MATH-500，base 正常作答的 474 题 | 73.0% | 71.7% | p=0.5716 |
| GSM8K，base 正常作答的 1316 题 | 77.3% | 75.5% | p=0.1292 |
| CE，长推理链语料（MATH-500 题目） | 1.000× | 1.330× | 漂移很小 |

整体准确率（production 口径，cap=4096，全部 run 同预算）：

| | base | vanilla | OneReplay C_mix |
|---|---:|---:|---:|
| MATH-500（500） | 69.20% | 68.40% | 69.40% |
| GSM8K（1319） | 77.10% | 75.44% | 78.70% |

配对 McNemar vs base 全部不显著：MATH-500 p=0.7376 / p=1.0000，GSM8K p=0.1678 / p=0.1477。

**量程本身不够**：MATH-500 配对可分辨下限 3.51pp、GSM8K 2.26pp，而遗忘量是 0.8pp / 1.67pp。要让 GSM8K 那 1.67pp 达到 80% 功效需约 5000 题（现有 1319），MATH-500 的 0.8pp 需约 20000 题。所以「不显著」是设计的必然。

## 1.2 被遗忘的是生成行为（五个指标同向）

| 指标 | base | vanilla | C_mix |
|---|---:|---:|---:|
| GSM8K 缺 `####` | 0.2% | **22.4%** | 0.2% |
| GSM8K strict 准确率 | 76.27% | **45.41%** | 77.86% |
| 不终止率（顶到自身上限） | 0.4%（5 题） | 1.2%（16 题） | 0.2%（3 题） |
| IFEval strict prompt | 66.54 | 55.08 | 待补 |
| Multi-IF 平均 prompt | 49.47 | 31.47 | 待补 |

strict 与 production 相差 30.03pp = **396 题的分完全靠「取全文最后一个数字」的兜底**（295 题无标记 + 约 100 题写了 `####` 但后面没数字）。

## 1.3 方法论发现（可独立成立的贡献）

**带宽松兜底的准确率基准会系统性隐藏灾难性的生成行为退化。** 30 个点的格式崩溃在 production 口径下被压缩成 1.67pp 不显著差异。只读 `summary.json` 无法发现。

⚠️ math500 探针有 29/473 行（6.1%）顶到 max_len=2048，CE 只覆盖答案前缀。

**MBPP 第一次拿到显著**（数学侧在任何准确率指标上从未做到）。

## 2.2 但失败分桶显示 MBPP 那 3.8pp 仍是输出结构问题

MBPP（题数，不是百分比）：

| 桶 | base | vanilla | 变化 |
|---|---:|---:|---:|
| **语法错误（不是合法 Python）** | 2 | **43** | **+41（21 倍）** |
| 断言失败（能跑，答案错） | 185 | 182 | **−3** |
| 名字/属性错误 | 58 | 29 | −29 |
| 类型/取值错误 | 36 | 49 | +13 |
| 通过 | 215 | 196 | −19 |

**断言失败纹丝不动（37.0% → 36.4%），全部下降由语法错误暴涨承担。** 断言失败这一桶测的是**算法内容**对不对，它持平意味着：只要模型还能产出可运行的代码，答案和之前一样正确。

细节支持这个读法：名字/属性错误**减少 29 题**，同时语法错误增加 41 题——原来能产出「能解析但引用了不存在的东西」的那批题，现在连合法 Python 都不是了。失败沿同一轴变深。

HumanEval 形态相反：语法错误几乎没动（1→3 题），**断言失败 56→64 题（34.1%→39.0%）**。这是本项目**唯一一处能力退化的迹象**，但 p=0.0987 不显著（量程 6.55pp，观测 6.10pp），且有替代解释（`cleanup_completion` 还在 `\nprint(`、`\n# Example` 处截断，写得更懒也会产出「合法但不对」的代码）。

为什么两个 benchmark 不同：HumanEval 给函数签名 + docstring，模型**续写函数体**，难跑偏成散文；MBPP 要求从零写完整函数，任何前言都会踩 `\ndef ` 截断。

## 2.3 未解决的概念问题（用户提出，很关键）

> 在代码里格式能力出问题，不就等于代码能力下降了吗？

**答：一半对。** "SyntaxError" 混了两件相反的事：

- **(a) 模型真的产出非法 Python** → 确实是编码能力退化
- **(b) 模型产出合法代码但裹了废话，判分器把代码扔了留下废话** → 代码本身是好的，丢的是「只输出代码」的指令服从度

两者在 pass@1 上一样，含义相反。**可以直接查**——`completion` 字段就在磁盘上。

无论查出哪种，断言失败持平这个事实不变：退化的不是「知道怎么解题」，而是「能不能写成规范完整可解析的输出」。

更准确的词：**输出结构 / 生成行为** vs **任务内容 / 算法内容**。用户直觉里对的那部分是：在代码上，输出结构的损坏有**直接的功能后果**（吐不出可解析代码的模型就是不可用的），这跟数学不一样（`####` 只是评测约定，兜底还能捞回来）。

所以代码结果不是数学结果的弱化版，是**补完**：

| | 同一种损坏 | 后果 |
|---|---|---|
| 数学 | CE 漂移 7.5 倍 | 被宽松判分掩盖成 1.67pp 不显著 → 方法论警告 |
| 代码 | 语法错误 21 倍 | 直接变成 −3.80pp 且显著 → 损坏真的有代价 |

## 2.4 为什么不能直接开训 code OneReplay：功效不够

| | n | vanilla 掉幅 | 量程 | 显著？ |
|---|---:|---:|---:|---|
| MBPP | 500 | −3.80pp（19 题） | 3.30pp | 是（刚过） |
| HumanEval | 164 | −6.10pp（10 题） | 6.55pp | 否 |

若 OneReplay 也消除 60%，MBPP 上救回约 11 题 = **2.28pp < 3.30pp 量程，测不出来**。要让 2.28pp 达到 80% 功效需约 **2100 题**（MBPP test 只有 500）。两个合起来 664 题也只把量程压到 2.97pp，仍差一口气。

**结论：pass@1 够用来发现伤害（勉强），不够用来测保护。**

# 第五部分　已踩过的坑（务必保留）

## 方法论

1. **C 只在 `q_proj,v_proj` 上采过。** 扩 target_modules 必须重采 C，否则 `lora_covariance_regularizer` 对没有 C 的模块**静默跳过**（只计入 `missing_layers`），等于只约束 q/v、其余自由漂移。**只提 rank 不需要重采**（C 形状是 `d_in × d_in`，与 rank 无关；`scale=alpha/r` 已在公式里）。
2. **`down_proj` 的 C 特别贵**：输入是 intermediate_size(6144) 不是 hidden(2048)，单层是别人的 9 倍，all-linear 全套约 7 GB（现在 qv 版 0.875 GiB）。折中选 `q,k,v,o`（全 2048²，约 1.9 GB）。
3. **提 rank 大概率无效**：r=8 已把新任务学穿（val loss 12.815 → 0.04494），没有剩余梯度压力驱动新增容量。
4. **λ 换配置必须重调**：用 `--replay_lambda 0 --measure_replay_when_lambda_zero 1` 跑几百步读 reg 量级，按 r=8 时 λ·reg 占 task loss 6.4% 的比例反推。
5. **in-pool 语料不能作独立证据**：`metamath_cpool` 是 C_math 的采集源，C_mix 在那儿的优势是自我加分的。

## 流水线

6. **`summary.json` 不记录 `MATH_MAX_NEW_TOKENS`。** 用 `responses.jsonl` 的 token max 反推：截断的 run 会把最长回复钉在预算上。**已发生过一次事故**：base/vanilla 卡在 1792、cmix 用 4096，混在同一目录几周未发现。
7. **`evaluate` 的「已有 summary.json 就跳过」会挡住重评。** 改预算/改判分逻辑后必须先归档旧目录。`LIMIT>0` 的冒烟结果**必须改道到独立目录**（我在 38/39 号里做了自动加 `_limit<N>` 后缀）。

# 第六部分　还不能声称什么

- **不能说 OneReplay 保护了数学能力**——没有能力损失可保护。能说的是保护了生成行为，以及在数学题上消除了 62~72% 的行为漂移。
- **不能说 C_math 是必要的**——3~5pp 优势尚无误差棒，MATH-500 那一档只有 1% 相对差，且池内那一档不能算证据。
- **不能说找到了数学能力真会退化的配置**——两个数据点都指向「这个新任务打不到数学」。
- **不能说代码能力退化了**——MBPP 的断言失败持平，HumanEval 的断言失败上升但不显著且有替代解释。步骤 0 会给出更确定的答案。
- **其他缺口**：纯 C_math 的 run 未评测；cmix 的 IF 侧未确认；全部结果只有 seed 1；`compare_cov_scale` 的层覆盖是每 8 层抽 1 层。
